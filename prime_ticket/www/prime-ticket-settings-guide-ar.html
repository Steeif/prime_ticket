حالة التنفيذ الحالية

معظم الحقول موجودة وتحفظ قيمها، لكن كود معالجة التذاكر لا يستخدمها حالياً. لذلك فإن التعيين التلقائي، ومراقبة اتفاقية مستوى الخدمة، وسير العمل المخصص، والإغلاق والتصعيد المجدول، ومفاتيح الإشعارات، ورمز API، والـ Webhook، وقواعد JSON لا تفعّل هذه الوظائف بعد. شعار التطبيق هو الاستثناء: يظهر في هذه الصفحة ونموذج إرسال التذكرة عند ضبطه. رسائل البريد الحالية تعتمد على سجلات الإشعارات التي ينشئها التطبيق في Frappe.

01

الإعدادات العامة

اسم التطبيق يُحفظ لكنه لا يغيّر واجهة التطبيق حالياً. شعار التطبيق يظهر في هذا الدليل ونموذج إرسال التذكرة عند رفعه. خيارات التعيين التلقائي هي Round Robin وLeast Busy وSame Category وRandom، لكن النظام لا يعيّن التذاكر تلقائياً بأي منها. مفتاحا البريد وSLA لا يفعّلان الإشعارات أو تتبع المهل. مهلة الاستجابة الافتراضية المعروضة هي 24 ساعة.

02

إدارة المشغّلين

جدول مشغّلي الدعم يختار سجلات المشغّلين. يحتوي ملف المشغّل على مستخدم Frappe وفئاته وسعته ومهارته وأوقات عمله ومنطقته الزمنية وتوفره وصلاحياته. هذه البيانات لا توزّع التذاكر ولا تمنح أدواراً تلقائياً. أضف دور Ticket Operator للمستخدم من شاشة المستخدمين في Frappe.

03

إعداد سير العمل

تُحفظ حالات سير العمل المخصص مع الوصف واللون والترتيب، لكنها لا تغيّر خيارات الحالة الثابتة في Support Ticket: Open وWorking in Progress وPending وWaiting for Reply وResolved وReopened وClosed. الإغلاق التلقائي مضبوط افتراضياً على 7 أيام والتصعيد التلقائي على 3 أيام؛ ولا توجد مهمة مجدولة تستخدم هاتين القيمتين حالياً.

04

فئات التذاكر

يختار هذا القسم سجلات Prime Ticket Category التي تحتوي على الاسم والوصف واللون والأيقونة وحالة التفعيل. نموذج العميل يستخدم حالياً خيارات ثابتة: Question (سؤال)، Bug Report (بلاغ عن خطأ)، Feature Request (طلب ميزة)، How-To (طريقة الاستخدام)، وOther (أخرى). تغيير قائمة الإعدادات لا يغيّر خيارات النموذج.

05

سياسات SLA

يحفظ كل صف أولوية التذكرة ومدة الاستجابة بالساعات ومدة الحل بالساعات ولوناً اختيارياً. تُعدّل السياسات داخل إعدادات برايم تكت لأنها جدول فرعي، وليست DocType مستقلاً في مساحة العمل. لا يحسب التطبيق المهل حالياً ولا يرسل تنبيهات عند تجاوزها.

06

إعدادات الإشعارات

ينشئ التطبيق حالياً إشعارات Frappe عند إنشاء تذكرة وعند تغيير حالتها إلى Resolved أو Waiting for Reply أو Reopened. مفاتيح الإشعارات الثلاثة وقالب البريد المخصص لا تتحكم بسجلات الإشعار هذه. اضبط البريد الصادر في Frappe وأدر قواعد الإشعارات من DocType Notification.

07

قواعد التصعيد

يحفظ المفتاح وصفوف مستويات التصعيد ومدة الانتظار بالأيام والدور المطلوب إشعاره، لكن لا توجد حالياً عملية مجدولة تستخدم هذه القيم.

08

التكاملات

تفعيل الوصول الخارجي عبر API لا ينشئ نقطة API. لا يقرأ التطبيق حقل رمز API ذي نوع Password ولا يتحقق منه، كما لا يرسل أحداثاً إلى رابط Webhook. استخدم مصادقة Frappe للـ API وصلاحيات مستخدم Frappe المرتبط. لا تضع سراً إنتاجياً في حقل الرمز متوقعاً أن يفعّل الوصول.

09

الإعدادات المتقدمة

حقلا الحقول المخصصة وقواعد العمل بصيغة JSON لا يجري تحليلهما أو تطبيقهما حالياً. خيار السماح للعملاء بإعادة تعيين التذاكر لا يغيّر الصلاحيات ولا يضيف إجراء إعادة تعيين.

ما الذي يعمل حالياً؟

✓ أدوار Frappe وصلاحيات DocType تتحكم في الوصول إلى التذاكر.

✓ يسجل إنشاء التذكرة المستخدم الحالي وبريده الإلكتروني عند توفره.

✓ خيارات الحالة معرفة بشكل ثابت في Support Ticket.

✓ يسجل النظام وقت الحل عند اختيار Resolved ويمسحه عند العودة إلى حالة نشطة.

✓ ينشئ التطبيق إشعارات Frappe للأحداث المذكورة أعلاه.
