Prime Ticket Settings

A practical guide to every section in the settings form, including what is active in the current app version.

Open Prime Ticket Settings →
Implementation status

Most settings fields are currently stored configuration and are not read by ticket handling code. Assignment, SLA monitoring, custom statuses, scheduled close/escalation, notification switches, API token, webhook, and custom JSON rules do not currently activate those features. This guide identifies those limits so settings are not mistaken for active automation.

01

General Settings

Application Name is stored but not applied to the UI. Application Logo appears on this guide and the Submit a Ticket form when configured. The auto-assignment controls offer Round Robin, Least Busy, Same Category, and Random, but none currently assigns tickets. The email and SLA switches also do not control notifications or start SLA tracking. The default response target is 24 hours.

02

Operators Management

Support Operators selects operator records. Operator profiles store a linked Frappe user, categories, capacity, skill, availability, working hours, timezone, and capability flags. They do not currently route tickets or grant roles. Assign the Ticket Operator role to users separately in Frappe.

03

Workflow Configuration

Custom workflow rows store a status name, description, color, and order, but Support Ticket still uses its fixed statuses: Open, Working in Progress, Pending, Waiting for Reply, Resolved, Reopened, and Closed. Auto-close defaults to 7 days; auto-escalate defaults to 3 days. No scheduled jobs currently use these values.

04

Ticket Categories

This section selects Prime Ticket Category records (name, description, color, icon, active flag). The customer form currently uses fixed choices: Question, Bug Report, Feature Request, How-To, and Other. Changing this settings list does not update the form choices.

05

SLA Policies

Each child row holds a priority, response target in hours, resolution target in hours, and optional color. Policies are edited inside Prime Ticket Settings; they are not standalone DocTypes in the workspace. The app does not currently calculate deadlines or alert on SLA breaches.

06

Notification Settings

The app currently creates Frappe notifications for new tickets, Resolved, Waiting for Reply, and Reopened. The three notification switches and custom email template do not control those Notification records. Configure outgoing email in Frappe and manage active notification rules under Notification.

07

Escalation Rules

The switch and child rows describe escalation levels, wait in days, and a role to notify. They are stored only: no scheduled escalation process currently reads them.

08

Integrations

Enable External API Access does not create an endpoint. Prime Ticket does not read or validate the Password-type API Token, and no code sends events to Webhook URL. Use Frappe API authentication and the linked Frappe user's permissions for integrations; do not treat this token field as active API access.

09

Advanced Settings

Custom Fields (JSON) and Custom Business Rules (JSON) are text fields that are not currently parsed or applied. Allow Customers to Reassign Tickets does not currently change permissions or add a reassignment action.

What is active now?

✓ Frappe roles and DocType permissions control ticket access.

✓ Ticket creation stamps the signed-in user and their email.

✓ Status choices are defined on the Support Ticket DocType.

✓ Resolved tickets get a resolution timestamp; active statuses clear it.

✓ App-created Frappe notifications send on the events listed above.
